## 1. FULL PROPERTY GRID FOR EDITING (Highest Priority)

This is the **single most important missing feature**. In EPA SWMM5, clicking ANY object on the map or project tree opens a property editor panel. Without this, the app is a viewer, not an editor.

### 1.1 Property Grid Component Architecture

Build a reusable`<PropertyGrid>` component that renders as a two-column table (Property Name | Value) docked to the right side of the map, exactly like EPA SWMM5.

```javascript
// Core PropertyGrid component specification
// This should be a single reusable component used for ALL object types

PropertyGrid Props:
  - objectType: string     // "junction", "conduit", "subcatchment", etc.
  - objectId: string       // The selected object ID
  - data: object           // Current property values from the model
  - schema: FieldSchema[]  // Defines every editable field
  - onChange(field, value)  // Callback when user edits a value
  - onOpenSubEditor(field)  // Callback when user clicks "..." for complex fields

FieldSchema:
  - name: string           // e.g., "Invert Elevation"
  - key: string            // e.g., "invertElev"
  - type: "number" | "string" | "enum" | "boolean" | "readonly" | "subdialog"
  - units: string | null   // e.g., "ft", "ac", "%"
  - enumValues: string[]   // For dropdown fields
  - min: number | null     // Validation
  - max: number | null     // Validation
  - required: boolean
  - helpText: string       // Tooltip on hover
  - category: string       // Group header: "General", "Geometry", "Inflows", etc.
  - subEditorType: string  // "inflows", "treatment", "lidusage", etc.
```

class SWMMModel {
  // Data stores

  patterns: Map<string, PatternData>
  options: AnalysisOptions
  
  // Methods
  getObject(type, id): any
  setProperty(type, id, field, value): void  // triggers map redraw
  addObject(type, data): string              // returns new ID
  deleteObject(type, id): void
  toINP(): string                            // serialize to .inp text
  fromINP(text: string): void                // parse .inp text
  
  // Event system
  on('change', callback)    // notify UI of model changes
  on('select', callback)    // notify property grid of selection
}

## 2. RESULTS POST-PROCESSING (Second Highest Priority)

### 2.1 Binary Output File Parser

SWMM writes results to a binary`.out` file. The web app needs to parse this either:
- **Option A**: Server-side (Node.js reads the binary file, serves JSON via API)
- **Option B**: Client-side (WASM-based parser or JavaScript binary reader)

```
SWMM .out file structure:
├── Header
│   - Magic number, version, flow units
│   - Number of subcatchments, nodes, links, pollutants
│   - Object names (ID strings)
│   - Reporting variables per object type
│   - Report start date, report step (seconds)
│
├── Computed Results (repeated for each reporting time step)
│   - Subcatchment results: rainfall, snow depth, evap, infil,
│     runoff, GW flow, GW elev, soil moisture, pollutant washoff
│   - Node results: depth, head, volume, lateral inflow,
│     total inflow, overflow, pollutant concentration  
│   - Link results: flow, depth, velocity, volume, capacity,
│     pollutant concentration
│   - System results: air temp, rainfall, snow, evap, runoff,
│     dry weather inflow, GW inflow, RDII, direct inflow,
│     total lateral inflow, flooding, outflow, storage volume,
│     evap loss, seepage loss
│
└── Footer
    - Object ID pointers, reporting period count
    - Error code, magic number (for validation)

// JavaScript binary reader:
class SWMMOutputReader {
  constructor(arrayBuffer) { }
  
  getSubcatchResult(id, variable, timestep): number
  getNodeResult(id, variable, timestep): number
  getLinkResult(id, variable, timestep): number
  getSystemResult(variable, timestep): number
  
  getSubcatchSeries(id, variable): {time: Date, value: number}[]
  getNodeSeries(id, variable): {time: Date, value: number}[]
  getLinkSeries(id, variable): {time: Date, value: number}[]
  
  getTimesteps(): Date[]
  getReportingVariables(objectType): string[]
  
  // Summary
  getNodeSummary(id): { maxDepth, maxHead, maxInflow, maxFlooding, ... }
  getLinkSummary(id): { maxFlow, maxVelocity, maxDepth, ... }
}
```

### 4.2 Save / Download .inp File

```
CRITICAL for editing to be useful:

- "File → Save" button triggers download of the current model as .inp
- Round-trip fidelity requirements:
  1. Load example.inp
  2. Make no changes  
  3. Save → output should be byte-for-byte identical (or minimal whitespace diffs)
  4. Make one change (e.g., junction invert)
  5. Save → only that one value should differ in a text diff

IMPLEMENTATION:
- Maintain the original .inp section order
- Preserve comment lines (lines starting with ;;)
- Preserve blank lines between sections
- For sections the UI doesn't edit, pass through verbatim
- Use consistent number formatting (match EPA SWMM's defaults):
  - Elevations: 2 decimal places
  - Areas: 2-4 decimal places
  - Roughness: 4 decimal places
  - Percentages: 1-2 decimal places
```
