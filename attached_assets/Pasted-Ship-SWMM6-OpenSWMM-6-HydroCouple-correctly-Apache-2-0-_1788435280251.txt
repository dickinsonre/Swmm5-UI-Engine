Shipping SWMM6 with the right notice
Verified live against the repo on 2026-09-03. Not legal advice — this is the mechanical checklist, and anything with real stakes goes past a lawyer.

1. The branch trap — check this first, every time
github.com/HydroCouple/openswmm.engine is not one license:

| Branch | LICENSE file | Copyright line | |---|---|---| | main | MIT | Copyright (c) 2025 HydroCouple | | swmm6_rel (the 6.0.0 line Bob builds) | Apache License 2.0 + a NOTICE file | Copyright 2026 HydroCouple Developers |

GitHub's repo sidebar shows "Other License" because of this split. So the answer to "what license is SWMM6?" is Apache-2.0, from swmm6_rel — which is what Corinne states publicly and what the alpha program means. Never quote the main README's MIT line for a 6.0.0 build.

Before shipping, record the branch and commit you took code from, and re-read LICENSE and NOTICE at that commit. An alpha moves.

2. When the conditions actually bite
Apache §4 conditions attach to redistribution, not use. Running the engine to produce results, or publishing the .rpt numbers, triggers nothing.

Everything Bob normally does does trigger it:

a GitHub repo or gist containing OpenSWMM source (Source form)
a compiled .wasm / .js engine artifact on Netlify or Pages (Object form)
a single-file .html with the engine base64-embedded via SINGLE_FILE — still distribution of Object form, and the easiest one to forget
an npm package or a zip with the engine inside
3. The four conditions, in Bob's terms
(a) Give recipients a copy of the License. Ship the full Apache-2.0 text — a LICENSE file in a repo; for a single-file app, either an About/credits view containing it or a link plus the file alongside the deploy. An SPDX tag alone is not "a copy".

(b) Mark files you changed. The WASM recipe patches three OpenSWMM sources (see swmm-wasm-build). Each patched file needs a prominent notice at the top that it was modified, by whom, and when — e.g. // Modified 2026-08-14 by Robert Dickinson: -fexceptions build fix for Emscripten. This is the condition most often missed on a fork.

(c) Retain the notices already in the files. Copyright, patent, trademark, and attribution notices in the source headers stay put — do not strip EPA-SWMM provenance headers when refactoring or minifying.

(d) Reproduce the NOTICE file. swmm6_rel has a NOTICE, so this one is mandatory. Reproduce its attribution notices in at least one of: a NOTICE file shipped with the work, the source or accompanying docs, or a display the work generates where third-party notices normally appear — which, for a single-file app, is the About/Credits panel.

Single-file HTML app (the common case)
Two placements, both cheap:

An HTML comment at the top of the file (survives View Source, not minification):
```html

  Bundles the OpenSWMM 6 engine (WASM).
  OpenSWMM Engine — Copyright 2026 HydroCouple Developers.
  Licensed under the Apache License, Version 2.0.

A Credits / Licenses section in the About panel carrying the full NOTICE text and either the Apache-2.0 text or a link to it. This is the §4(d) "display generated by the Derivative Works" route, and it is the one that actually satisfies the condition — the comment alone is thin if the file is minified or wrapped.
Gist
A gist with the engine in it is redistribution. Add the comment block above as the first lines, and a second file in the gist named NOTICE. Gists take multiple files — use that instead of skipping it.

Paper, slide, or blog credit (courtesy, not the license)
Simulations used OpenSWMM 6.0.0-alpha (HydroCouple), Apache-2.0, https://github.com/HydroCouple/openswmm.engine, commit <sha>. Lead developer Caleb Buahin; developer/documentation Corinne Wiesner-Friedman.

6. What the license does not do
No copyleft. Apache-2.0 is permissive. Bob's own app code can carry any license he likes; the notices travel with the engine, that's all. Nobody has to open-source their app to embed the engine.
No claim on the EPA lineage. The public-domain SWMM material stays public domain — the Apache grant does not reach back over it, and recipients keep rights they already had.
No trademark license (§6). "EPA", "USEPA", and "SWMM" may be used to describe origin only. Never imply EPA endorsement, and don't name a product in a way that reads as an official EPA or HydroCouple release.
Patent grant with a termination clause (§3): suing over patents in the work ends the patent grant.
Change notices are required on derivatives, but the licensor's names may not be used as endorsement — a derivative should not be presented as "SWMM6" itself.
7. Alpha program
SWMM6 is open-source alpha; structured feedback goes through the form Corinne posted: https://forms.gle/Cf3JaNpQ1suGn8kt5. Development leads are Caleb Buahin (lead developer/maintainer) and Corinne Wiesner-Friedman (developer, documentation, technical review), both former EPA research engineers, with Scott Jeffers on documentation and outreach. docs/authors.md in the repo credits Lew Rossman, Wayne Huber, Larry Roesner, and lists Robert Dickinson under SWMM 5 review and testing — so Bob is already in the authors file, which is a fine thing to cite and no substitute for §4.
