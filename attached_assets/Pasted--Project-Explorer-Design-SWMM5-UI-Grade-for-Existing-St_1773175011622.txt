# Project Explorer Design — SWMM5-UI

## Grade for Existing Streamlit App: **B+ (85/100)**

| Category | Score | Notes |
|---|---|---|
| **Parsing** | 9/10 | Solid multi-section parser, good encoding detection |
| **Visualization** | 8/10 | Rich chart variety, but no network/map rendering |
| **UX/Polish** | 7/10 | Themed well, but Streamlit limits interactivity |
| **Architecture** | 7/10 | Monolithic — parser not separated from UI |
| **SWMM Domain** | 8/10 | Covers major sections, missing LID, Controls, RDII |
| **Performance** | 8/10 | Good for medium files; 200MB limit is generous |
| **Extensibility** | 7/10 | Streamlit makes it hard to add features like a Project Explorer |

**Summary**: Strong analytical tool for viewing INP data. The gap is that it's a *viewer*, not a *modeler*. A Project Explorer is exactly the feature that bridges that gap.

### 2. Interaction Model

#### Click Behavior

| Action | Target | Result |
|---|---|---|
| **Single click** on group header |`Network Nodes`| Expand/collapse the group |
| **Single click** on leaf item |`Junctions (5)`| Open data grid in center panel showing all junctions |
| **Double click** on leaf item |`Junctions (5)`| Open data grid + auto-fit columns |
| **Single click** on options sub-item |`Hydraulics`| Open the options editor for that category |
| **Click** on`Title / Notes`| — | Open a text editor for the TITLE section |

#### Right-Click Context Menus

**On a data leaf item** (e.g.,`Junctions (5)`):

```
┌──────────────────────────────┐
│ 📋 View Table                │
│ 📊 Summary Statistics        │
│ ─────────────────────────    │
│ ➕ Add Junction...           │
│ 📥 Import from CSV...       │
│ 📤 Export to CSV...          │
│ ─────────────────────────    │
│ 🗺️ Zoom to All on Map       │
│ 📈 Quick Chart...        ▸  │
│   ├── Histogram              │
│   ├── Box Plot               │
│   └── Scatter Matrix         │
│ ─────────────────────────    │
│ 🔍 Find in Map...           │
│ 🏷️ Filter by Tag...         │
└──────────────────────────────┘
```

**On a group header** (e.g.,`Network Nodes`):

```
┌──────────────────────────────┐
│ 📋 Expand All Children       │
│ 📋 Collapse All Children     │
│ ─────────────────────────    │
│ 📊 Group Summary             │
│ 📤 Export All to CSV...      │
└──────────────────────────────┘
```

#### Drag and Drop

- Drag an INP file onto the Project Explorer → loads the file
- Drag a CSV file onto a leaf item (e.g.,`Junctions`) → prompts import dialog with column mapping

### 3. Visual States

```
State Indicators:
─────────────────
● Junctions (5)        ← Blue dot: has data, no issues
⚠ Conduits (6)         ← Warning: validation issues found
✓ Outfalls (1)         ← Green check: validated, all good
○ Dividers (0)         ← Empty circle: section exists, no data
  Snow Packs (0)       ← Dimmed text: section not present in INP

After Simulation:
─────────────────
● Junctions (5) 📊     ← Chart icon appears: results available
```

#### Badge Counts

Counts update reactively. When a user adds a junction via the map or grid,`Junctions (5)` immediately becomes`Junctions (6)`.

### 4. Search / Filter Bar

At the top of the Project Explorer panel:

```
┌─────────────────────────────────┐
│ 🔍 Search sections or items... │
└─────────────────────────────────┘
```

**Behavior:**
- Typing`junc` filters tree to show only`Junctions`
- Typing`J1` searches across all sections for any element named`J1`, highlighting the matching section and scrolling to it
- Typing`elev > 100` performs a quick filter across numeric fields (power-user feature)
-`Esc` clears the search

### 6. State Synchronization — The Key Design Principle

The Project Explorer must stay in perfect sync with three other panels:

```
┌─────────────┐    ┌──────────────┐    ┌──────────────────┐
│   Project    │◄──►│  Map Canvas  │◄──►│  Property Editor  │
│   Explorer   │    │   (center)   │    │   (bottom/side)   │
└──────┬───────┘    └──────┬───────┘    └──────────────────┘
       │                   │
       └───────┬───────────┘
               ▼
       ┌───────────────┐
       │   Data Grid    │
       │ (center panel) │
       └───────────────┘
```

| User Action | Project Explorer Response |
|---|---|
| Click`J1` on the map | Explorer highlights`Junctions`, property editor shows`J1` |
| Delete`J1` in the grid | Explorer updates count to`Junctions (4)` |
| Add junction on map | Explorer updates count, flashes briefly |
| Run simulation | Result icons (📊) appear on sections with output |
| Click`Conduits` in Explorer | Map highlights all conduits, grid shows conduit table |

### 10. Suggestions for Your Existing Streamlit App

| Priority | Suggestion | Effort |
|---|---|---|
| 🔴 High | **Extract parser into a pip-installable package** — this is your most valuable asset | 2-3 days |
| 🔴 High | **Add LID_CONTROLS, LID_USAGE, CONTROLS parsing** — these are heavily used sections | 1 day |
| 🟡 Medium | **Add network graph visualization** — you already import NetworkX but the screenshot shows no map | 2 days |
| 🟡 Medium | **Add a simple tree/sidebar navigation** — even in Streamlit, you can approximate a Project Explorer with`st.sidebar` expanders | 1 day |
| 🟡 Medium | **Add INP file export** — let users edit a grid and write back to .inp | 2 days |
| 🟢 Nice | **Add cross-section profile viewer** for conduits | 1 day |
| 🟢 Nice | **Add longitudinal profile plot** (node-to-outfall path) | 2 days |
| 🟢 Nice | **Validate the model** — check for disconnected nodes, missing cross-sections, impossible slopes | 2 days |

The single most impactful upgrade path: **move from Streamlit to a React + FastAPI app** where this Project Explorer becomes the primary navigation paradigm, and the current Streamlit charts become the content panels. Your parser stays in Python on the backend; the Project Explorer, map, and grids move to the browser where they belong.
